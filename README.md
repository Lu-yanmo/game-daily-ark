# 明日方舟端游每日清体力（MAA + 计划任务，无人值守）

每天 08:00 / 20:00 自动把方舟端游的日常跑完：**公招 / 基建 / 信用 / 领奖 + 把当天理智刷干**，
跑完自动收尾（关 MAA、关端游）。理智刷什么由脚本判断：有活动刷活动图，长草刷常驻材料本。

用的还是 **MAA** 本身 —— 这里只做「今天该刷什么 → 改 MAA 配置 → 拉起端游和 MAA → 看日志判断结果 → 收尾」。

**怎么上手最快**：去 [Releases](https://github.com/Lu-yanmo/game-daily-ark/releases) 下载 `game-daily-ark.exe` 和
`game-daily-ark-engine.zip` 这一对附件，放同一个文件夹，双击 exe 就直接进主控台（零依赖，不用装任何东西）。
之后的日常全在面板里点，见 [第 1 节](#1-日常操作双击-panelcmd-就够了)。从源码跑、或者想接自动化，见 1.2 / 1.3。

## 0. 用之前先看这四条

- **本仓库只有我原创的脚本与源码（PowerShell / C# / Rust，少量 Python），不含 MAA、不含端游客户端、不含任何游戏素材。** MAA 是 AGPL-3.0 的第三方软件，端游要你自己从官方渠道装（许可见 [第 8 节](#8-许可免责与隐私)）。脚本只是启动 MAA、读它的日志和配置文件。
- **游戏用户协议禁止脚本/自动化。** 这类工具在圈子里被默认容忍 ≠ 官方许可；处罚风险由使用者自行承担，建议只在个人账号上用。
- **判定逻辑和 MAA 版本强耦合。** MAA 升级后改了 `gui.log` 文案或配置字段，判定就可能失效，所以脚本在「日志在涨却一条认识的标志都没有」时明确报 `unknown-format`，并且**不会**据此判定日常已清完。看到这个状态按 [第 6 节](#6-出问题怎么查) 对一遍日志，再改判定规则 —— 规则的真身已经不在 `lib\maa.ps1` 里（那份文件现在是冻结的转发壳，它头注里写着指路），而是在 `tools\panel-cs\` 与 Rust 核 `tools\rustcore\` 里；改完用一轮已经跑过的真日志离线回放验证，不用重跑游戏。
- **定时跑的那一刻，Windows 会话最好别处于锁屏状态。** 无人值守那几轮反复出现同一个样子：MAA 认得到登录界面的 START、
  每 4 秒点一次、点三百下界面都不动，而人在机器前手动跑完全正常。原因还没定死（锁屏/拿不到前台是头号嫌疑，但**不是**
  早先写的「MAA 退化成发消息」——它的点击一直是发消息，成功轮也是），详见 [第 2.2 节](#22-无人值守那一轮为什么可能认到按钮却点不动)。

**默认策略里有两条是硬编码的偏好，先说在前面**：

- **不吃理智药**：脚本每次都会把 `UseMedicine / UseStone / UseExpiringMedicine` 压成 `false`。
- **不自动打没打过的新活动**：版本更新出了新活动时，每一轮都会拿活动最后一关当探针机器自证 —— MAA 认库后的关卡名单里进得去才刷活动图，进不去就当日改刷长草（理智照烧、不空放），你手动打通后下一轮自动切回（第 3 节门 1）。

## 1. 日常操作：双击 `panel.cmd` 就够了

面板是**面向用户的主控台**：从今天跑什么、为什么这么判，到改配置、改时间点、翻历史、打包诊断，
都在界面里点，不需要记命令。（命令行还在，但位置是「兜底与自动化」，见 [1.2](#12-兜底与自动化命令行)。）

双击 `panel.cmd`（或不带参数打开打包好的 exe）会先用 **Windows 自带的 .NET 编译器**把
`tools\panel-cs\` 里那一组 `.cs` 现编成 `tools\panel-cs\panel-cs.exe`（几秒钟，不用装任何东西）再打开它 ——
那组文件是**同一份程序**的分工：GUI 面板、判定面、命令行动词表、以及各自配套的离线自检，`Panel.cs` 是入口那份。
这是一份**黑白双主题**的 C# 面板，右上角可以切深/浅。极精简系统上编不出来就明说编不出来、给命令行出路 ——
面板只有 C# 这一份实现，没有「回落 PowerShell 面板」那一路（2026-10-23 定案）。

左边一条导航，上面两项是「看哪一路的读数」，下面四项是主控台的四页：

| 页 | 干什么 | 落到哪儿 |
| --- | --- | --- |
| 总览 / 方舟 | 今天刷什么、两道门、下次几点跑、上一轮结果（带原因，点行看整句） | 只读 |
| 配 置 | 助手路径（MAA 目录、端游 exe）+ 视觉兜底与通知（模型名、Key、webhook） | 路径改动代跑 `setup.ps1`（探测/合并/备份归它）；视觉那几项行内写 `config\settings.json`，写前备份到 `backups\` |
| 定 时 | 把「机器上现在真注册着的 `GameDaily-*` 任务 + 下次触发」和 `schedule.times` 并排摆出来，改时间点、注册、卸载 | 代跑 `install-task.ps1` / `tools\reschedule-daily.ps1`（改时间点会等当前轮次跑完，弹一次 UAC） |
| 历 史 | `state\history.csv` 最近 12 轮，带原因的行可以点，整句打进下面的日志区；一键打开 `logs\` | 只读 |
| 诊 断 | 一键把「读数 / 体检 / 去掉 key 的配置摘要 / history.csv / 最近 5 个运行日志」打成 zip 落桌面 | 只读 + 打包 |

**面板外壳不做第二个判定**：界面上每一行结论都来自判定面那一份 `BuildDumpSummary`（真身 `tools\panel-cs\Panel.Summary.cs`，
在面板自己进程里算，它的输出就是判定层逐字写进 `state\history.csv` 的那套机器协议行 + 那句原因），
面板只转达、不改写。所以面板里看到的和命令行跑出来的是同一个。
「开始跑一轮」要连点两次才真的开跑。视觉 Key 只存在这台机器的 `settings.json` 里：不进命令行参数、不进日志、不进仓库，
诊断包里的配置摘要会把它的值抹掉（键名留着好看出配过没配）。
读数第一行是 `PROTO|<版本>`：判定层和面板对不上版本时，面板会在日志区明说「判定层协议 v几 / 我只认 v几」，
而不是让某个格子静默变空 —— 读不懂必须说出来。

C# 面板有三个不弹窗的自检：`tools\panel-cs\panel-cs.exe --selftest`（布局/主题链）、`--consoletest`
（四页取数、写配置的转义与备份、代跑参数怎么拼、诊断包里搜不搜得到 Key —— 全程只在 `settings.json` 的**临时副本**上写，
跑完逐字节比对确认原件没动）和 `--exptest`（「实验功能」那几个布尔键的读写回环：翻一次读得回来、只有那一行动过、
补出来的那一行要能被 JSON 解析器复述、形状认不出时必须拒着不写）。打包成 exe 的场合对应动词是 `--panel`。

### 1.2 兜底与自动化（命令行）

界面没做的边角、以及定时任务和脚本化调用走这里；下面这些和面板点出来的做的是同一套脚本。

| 想做什么 | 怎么做 |
| --- | --- |
| 看今天会怎么跑（**什么都不改、不启动**） | `pwsh -File status.ps1` 或 `pwsh -File daily-clear.ps1 -DryRun` |
| 手动跑一轮（**注册过任务后不再弹 UAC**） | 双击 `run-daily.cmd`，等价于 `pwsh -File run-via-task.ps1` |
| 每天按 `config\settings.json` 里 `schedule.times` 的时间自动跑 | `pwsh -File install-task.ps1`（注册计划任务，弹一次 UAC） |
| 第一次装：探测助手装在哪 | `pwsh -File setup.ps1`（见第 4 节） |

命令行常用姿势：

```powershell
.\daily-clear.ps1 -DryRun              # 预览：今天判定成什么、将要改哪些配置
.\daily-clear.ps1                      # 真跑一轮（会弹一次 UAC，除非走计划任务通道）
.\daily-clear.ps1 -ShopDone            # 「活动商店我已领空」→ 之后不再刷活动，剩余理智转长草
.\daily-clear.ps1 -ShopReset           # 误标了/活动又开新一批兑换 → 撤销领空标记
.\daily-clear.ps1 -Force               # 本轮忽略活动图的自证结论，强行按活动图刷
.\daily-clear.ps1 -Farm                # 本轮只刷目标材料缺口（ark.farmTargets 配的目标，见 3.5）
.\daily-clear.ps1 -Stage SK-5          # 临时指定刷某个关卡
.\daily-clear.ps1 -SkipCleanup         # 跑完不关端游（自己接着玩）
.\daily-clear.ps1 -NoElevate           # 禁止自动提权（只想看输出）
```

退出码：`0` 全部完成 / `1` 部分完成 / `2` 失败。运行日志在 `logs\`，历史汇总在 `state\history.csv`。

**为什么需要管理员**：明日方舟端游要管理员权限，MAA 未提权时连不上它（Windows UIPI 挡住输入注入），
表现是 MAA 一直停在「正在连接模拟器……」。三条路：

1. **计划任务通道（推荐，注册一次以后不再弹）**：`install-task.ps1` 除了两个每日任务，还会注册一个无触发器的
   按需任务（同样最高权限）。`run-via-task.ps1` 只负责点火、跟日志、回传退出码 —— 普通权限就能触发自己账号下的
   最高权限任务，所以**不弹 UAC**。按需任务不存在时自动退回直跑。
2. **自我提权**：直接跑 `daily-clear.ps1` 时若不是管理员，用同样参数以管理员身份重启自己，等子轮结束原样返回退出码（弹一次 UAC）。
   pwsh 若是 Microsoft Store(WindowsApps) 版，系统不允许直接对它提权，脚本会改用 `System32\cmd.exe` 做提权载体（UAC 上显示 cmd.exe，属正常）。
3. **`-NoElevate`**：不提权直跑，只对手动场景有意义（端游那一路大概率连不上）。

### 1.3 用 git 克隆的人：先决定「内置件」从哪来（拿不到就整轮拒跑）

**每天那一轮的默认实现只有一份，住在内置件 `gdcore.exe` 里**（核内十段骨架，源码在 `tools\rustcore\src\main.rs`，
`lib\rust-round.ps1` 是入口和它之间的转接层）。本仓库按「源码进仓、产物不入仓」的口径**只带 Rust 源码，
不带编好的 `gdcore.exe`**。而 PowerShell 那条十段兜底已于 2026-10-20 退役（真身删了），所以入口拿不到内置件时
**不再"换人跑"**，而是整轮拒跑：日志一句 `这一轮没跑：转接层拿不到内置件 gdcore.exe`，退出码 `2`。
面板上点「开始跑一轮」得到的是同一句 —— 面板不自己判定，也不自己补跑。

三条有出口的拿法，按省事程度排：

1. **走下载页那对附件（推荐给不碰命令行的人）**：`game-daily-ark.exe` 里内嵌整棵脚本树**和内置件**
   （打包链第 0 步就现场编 Rust，缺内置件宁可不打这枚 exe），第一次运行解到
   `%LOCALAPPDATA%\game-daily-ark\app\`，之后双击就行，不需要 cargo、不需要自己编任何东西。
2. **现场编**：`pwsh -File tools\rustcore\build.ps1`（要 Rust 工具链 `cargo`，普通玩家机器一般没有；
   找不到工具链它会把装它的命令印出来）。产物落在 `tools\rustcore\target\release\gdcore.exe`，
   那正是转接层找内置件的第二个位置。
3. **从跑过的机器上拷**：把同版本的 `gdcore.exe` 放到 `tools\rustcore\gdcore.exe`（转接层候选序的第一档，
   就是"随包走"那个位置），放好这一轮就起得来。

两条例行要说清的，免得照着老印象敲：

- **只想看今天会怎么判、不真跑一轮**：`pwsh -File status.ps1` 不碰内置件，克隆下来直接能看；
  但 `daily-clear.ps1 -DryRun` 走的是同一把闸，同样整轮拒跑（退出码 `2`）。
- **`GD_RUST_OFF=1` 或 `runtime.rustOff` 现在不再是「退回 PowerShell」**：那把主闸把内置件拨下线之后，
  这条路上已经没有 PS 十段可退，效果同样是拒跑并说清原因。要让这台机器别再来这一轮，按第 5 节卸掉计划任务。

## 2. 每天到底刷什么（自动判定）

核内每轮从 MAA 官方活动接口 `api.maa.plus/.../StageActivityV2.json` 取一次数（拉不到就退回 MAA 本地缓存
`cache\gui\StageActivityV2.json`）：

- 有进行中的活动关卡 → 理智全刷活动图（活动代币优先）；标记过「商店已领空」的活动会被跳过（第 3 节门 2）；
- 没有活动（长草）→ 按 `config\settings.json` 的 `ark.defaultStage` / `planByWeekday` 刷，默认 `CE-5,LS-5`
  （龙门币 + 经验，都是每天开放的常驻本；MAA 的「剩余理智」会按列表顺序把理智刷干）；
- 关卡代号建议对着 MAA 自带 `resource/stages.json` 核一遍再填。**材料本轮哪几天开放由游戏服务端决定，脚本不猜**：
  想固定刷某种材料，就把当天开放的关卡代号写进 `planByWeekday`（键 `1`=周一 … `7`=周日）。

### 2.1 被弹窗挡住时的视觉兜底（可选，默认开着）

MAA 认界面靠模板匹配，**它的模板集里没有的东西它就看不见**。最常见的坑：版本更新 / 节日活动后端游画面上盖一层新公告。
2026-09-25 撞上的是中秋那张「锦枫映月 · 月饼烘焙小教程」整屏活动页：它把主界面整个盖住，MAA 找不到任何一条链路的入口，
于是公招 / 基建 / 作战 / 商店 / 奖励一路报错跑空（实测 6 条链路 0 完成，`StartUp@CloseAnno` 连认 50 次认不出它右上角那个 ×）。
这种局 MAA 自己永远走不出来 —— 模板里没有那个关闭按钮，它就永远不会去点它。

判到"这一轮不对劲"有三个触发点，三个都会先给兜底一次机会再宣布失败：

- **MAA 在同一个子任务上反复点同一处、一条链路都没完成**（这一条最常用）。特征很具体：`asst.log` 里那个子任务的
  `exec_times` 一路涨（实测涨到 316）、模板分数始终 0.99，`gui.log` 却一个字不写 —— 点得动、但没被吃进去。
  脚本先把端游窗口抢到前台（"窗口收不到输入"是另一种卡法），**抢完立刻问一次画面，不再干等**：
  那 22 分钟本来也不会自己变好。只点了一两次数不算卡住，正常推进也会点。
- **MAA 自己宣布本轮跑完、但链路没跑齐**（`gui.log` 里的「任务已完成，但出现错误！」）→ 队列已经空了，它不会再自己动，
  所以**当场兜底一次，然后立刻判 `stalled` 早退**（2026-09-25 那轮就是在这里白等的：
  07:56 已经打出这句，脚本 08:19 才想起来看屏幕，兜底成功了也救不回来，一直耗到 08:41）。
  早退之后由外层那一次重试接手：它会关掉端游重开、重起 MAA 再跑一遍队列。实测这条路是通的——
  重开端游之后那张中秋页并没有再弹，重试那一轮 6 条链路全完成、约 12 分钟跑完。
- **asst.log 静默满 `runtime.stallTimeoutMinutes`（默认 22 分钟）** → 兜底一次；成功就把停滞计时清零继续等，失败就判 `stalled`。

判到卡住之后、宣布失败之前，脚本可以做一次兜底：把端游窗口截一张图交给视觉模型，让它回答「有什么挡住流程的东西、
该点哪里关掉」，然后由脚本在管理员通道里点那一下，并再拍一张比对，确认画面真的变了（没变就算没成功，不会连着点）。
这条链路已经在活体端游上走通过一次：兜底拍到 1296x760 的端游窗口 → 模型答「中秋活动月饼制作界面，点右上角关闭」
→ 脚本在客户区 (1164,93) 点了一下 → 再拍一张比对，画面粗结构变了 126 格 → 弹窗确实没了、回到主界面。

点那一下走的是**真实鼠标**（把端游窗口切到前台 → 移动指针 → 按下/松开左键 → 指针回到原来的位置）。
选它是因为这条路在这台机器上被反复确认点得动；裸往窗口发消息（`WM_LBUTTONDOWN` 带客户区坐标）实测过：消息返回成功、
坐标也正好压在弹窗的 × 上，弹窗却纹丝不动。**但别把它读成"这个端游不吃发消息"**——MAA 自己点击用的就是发消息
（配置项 `MouseMethod: PostMessageWithWindowPos`），人在机器前时它点得动；这两种"发消息"实现差在哪还没查清，
所以脚本保守地用真实鼠标。
所以兜底发生的瞬间你会看到游戏窗口跳到最前、鼠标动了一下 —— 不想被打断就别在用它的时候手动跑这一轮。
窗口如果被最小化了，脚本会先把它恢复再截图（最小化时拍到的只会是一张空图）。

- **只在异常路径触发**：正常一轮一个网络请求都不发。默认每轮最多兜底 2 次（`runtime.visionMaxRescue`）。
- **只准点「关闭」这一类，但可以试到 3 个点位**：一次问价模型最多回 3 个候选点位、按把握从大到小排，脚本逐个点，
  每点一下都补拍一张比对签名，谁点完画面真变了就算救活；三个都没动就明说"这一路走不通"，不会换个答案把上一步还回去。
  三次机会来自**同一次**问价：不额外花钱、不额外等模型。坐标超出客户区或落在标题栏的那几个先剔掉，
  一个可用点位都没有就直接放弃；抢不到前台时退回发消息（宁可点不动，也不会把真实点击打进你正在用的窗口）。
  提示词硬性禁止它点领取 / 前往参与 / 确定这类会推进游戏状态的按钮 —— **默认就是这样**。要放开这一档，
  得在面板「实验功能」卡里勾「允许领日常奖励」那一档（写 `runtime.visionAllowReward`，不勾 = 硬禁）：
  判错一次就是拿账号换一次不确定，所以这个开关默认不给。
- **要额外配两样东西**：一个视觉模型的 API key（阿里云百炼 / DashScope），和一个能跑的 Python 3。
  key 填 `runtime.visionApiKey` 或设环境变量 `DASHSCOPE_API_KEY`（环境变量优先，`settings.json` 不入版本库）。
  **没有 key 就不兜底**，只按原来的方式说明原因，不会报错卡住；不想用就在图形面板的「实验功能」卡把
  「端游兜底」那颗勾取消（等价于把 `runtime.arkVisionRescue` 改 `false`，写回前会把旧配置备份到 `backups\`；命令行改法照旧有效）。
  这张卡上**这一仓只会露出端游这一路用得上的开关**（「端游兜底」「允许领日常奖励」和那颗「只问不点」；模拟器那颗勾不会出现，
  因为这一仓没有模拟器那一路）—— 按名字找，别按第几颗找。
  Python 只在最后一步"把图发出去、把回答收回来"上出场（`tools\vision\ask.py`）；**截图、解析回话、换算点位、判断能不能点、
  点击，全部在主控进程这边**（C# 现编的现场手脚，见 `tools\gdinterop\`）。
  没有它就装一个：`pwsh -File setup.ps1 -WithPython` 会下载一个 embeddable 包到 `state\python\`（不进仓库），
  你自己装过 Python 3 就把 `runtime.pythonExe` 指过去。**没有可用的 Python 时兜底会说明原因后放弃，日常主流程不受影响。**
  为什么把"发请求"这一层交给 Python：`Invoke-RestMethod` 把"超时 / 连不上 / key 不对 / 端点写错 / 被限流"揉成同一句
  WebException，而兜底要回答的恰恰是"这次没问成，该改哪儿" —— Python 侧按状态码分类，429 / 5xx 还会退避重试。
  key 只经环境变量交给子进程：不进命令行、不进请求文件、不进日志、不进诊断包。
- **地址可以换**：`runtime.visionBaseUrl` 不限于百炼公共端点，任何兼容 OpenAI 的 chat/completions 接口、且**能接受图片输入**的
  服务都行（自建网关、套餐网关都可以）。末尾只写到 `/v1` 也没关系，脚本会自己补上 `/chat/completions`。
  模型名以那个服务实际支持的为准（`runtime.visionModel`，一般 `GET <base>/models` 能列出来）——写了它不支持的名字会直接
  404 `Model not exist`，那种情况下兜底只留一句"模型调用失败"就放弃，不会连着重试。
- **隐私**：兜底那一刻会把端游窗口的一张截图 POST 到 `runtime.visionBaseUrl` 指向的接口（默认是 DashScope 的
  OpenAI 兼容地址）。窗口里当时显示什么就可能发出去什么，所以这一步只在「已经卡住」时发生，且日志里不会记录 key。
- 模型默认 `qwen3.8-flash`（`runtime.visionModel`），换任何支持图片输入的 OpenAI 兼容模型都可以，只要它认这个响应格式。
- 兜底试过没成功，失败结论里会带一句「视觉兜底试过 N 次，最后一次……」；这条链子的离线自检在 `tools\test-ark.ps1`
  （全程不联网、不截图、不点击）。
- **救过几次、救活没有，是记下来的**：每一次兜底往 `state\rescue.json` 追加一条（哪一路、什么时候、结果那句原话，保留最近 60 条）。
  "这一轮到底兜了几次、有没有用"从此是可以查的，不是感觉。
- **想知道它到底看见了什么，用只问不点那条**：`pwsh -File tools\vision-ask.ps1 -Game ark` 把现屏交给模型、把回答原样打出来，
  **一次点击都不做**（面板「实验功能」卡上那颗「只问不点」就是代跑这一条）。调试"兜底为什么没救活"，跑它比改代码便宜得多。

### 2.2 无人值守那一轮为什么可能「认到按钮却点不动」

现象：定时那一轮 `ark` 报 `stalled`，`detail` 里写着「MAA 内核其实还在跑，卡在子任务 StartUp@GameStart，已重复 N 次」，
而 MAA 自己的 `debug\asst.log` 里模板匹配分数一直是 0.99 上下——**它认到了按钮，只是点不动**。
人在机器前手动跑的时候，同一个按钮一次就点过去了（2026-09-25 07:53 那轮实测：1 次点击、0 次真实注入，
走的还是配置里那个发消息通道），所以这不是"这个端游不吃发消息"，也不是 §2.1 那种窗口挡屏——那张活动页当时不在画面上。

先把已被日志证实的三条放在这儿（`debug\asst.log` 按动作归类数出来的，不是猜的）：

- MAA 的点击**一直**是「往窗口发消息」（`Win32Controller click` 那些行，对应配置项 `MouseMethod: PostMessageWithWindowPos`）；
  7600 多次点击没有一次走真实注入。所以「点不动」**不是**因为消息方式在无人时偷偷换了——成功轮用的也是同一套。
- 日志里的 `inject_input_event`（真实注入）**全部来自基建向左滑那一类拖动**，因此它的有无只能说明
  「这一轮走没走到滑动那一步」，不能拿来判断点击通不通。
- 卡住那一刻视觉兜底拍到的就是登录界面本身，START 按钮在那儿，上面没有窗口压着。

所以还留在候选里的是两件事，现有日志分不出谁是谁：**会话被锁 / 窗口拿不到前台**（这个端游可能要求窗口是活动状态才处理输入），
或者**有个 MAA 不认识的窗口在客户区外挡着**。脚本不再替这件事下结论，只做三件有把握的：

1. **启动 MAA 后先记一行 `点击环境探测：…`**——输入桌面叫什么（`Default` = 没锁屏）、端游在不在前台、前台是谁、
   窗口是否最小化/可见/矩形在哪、光标在哪。全是只读调用。
2. **判到「同一个子任务点了 60 次以上、一条链路都没完成」就先自己抢一次前台**（只改窗口状态，绝不往客户区点东西），再给 60 秒。
3. **仍在原地就早退**成 `stalled`，并把抢前台时看到的现场原样写进 `detail`——不再白烧 40 分钟，也不再写成一句没依据的话。

要定死原因，就看下一次定时轮那行 `点击环境探测`：**输入桌面不是 `Default` 就说明会话没在正常桌面上**，鼠标键盘本来就进不来。
真要跑通只有两条路：**把时刻挪到你人在机器前的时间**，或者**让那个时刻会话是解锁的**（关掉离开自动锁屏 / 把锁屏超时拉长，
属于系统设置，本仓库不替你改）。

### 2.3 全程盯一轮的第三方：监督 agent（可选，默认开着）

上面那道防线判"卡没卡住"的，正是干活的那个等待循环自己 —— 它要是以我们没想到的方式挂死，没有第二个声音会响。
监督 agent 补的就是这个位置：真跑一轮时，核内另起一个隐藏子进程（面板那枚现编程序的另一种身份：前台入口 `supervise-loop`，
规则与记账的真身是 `tools\panel-cs\Supervisor.cs` / `Supervisor.Host.cs`），每 60 秒拍一次现场证据
（MAA 日志多久没动、本轮主日志多久没动、MAA 进程还在不在、完成线出现过没有），规则先判；
**只有连续两拍判到静止**才拍一张端游画面问一句"有没有东西挡着主流程"（同一路线两次提问至少隔 5 分钟，正常一轮一个请求都不发）。

权限刻意收着：它**不点鼠标** —— 画面被弹窗挡住时只记录，点窗是 2.1 那套兜底的活，两边抢同一个鼠标更糟；
唯一的干预是**重启 MAA**（它启动即自动开队列，风险只是多跑一遍），一轮最多 1 次，其余异常只发通知（webhook/气泡）。
每一拍落在 `state\supervision.json`（面板环境卡的「监督」行转达它：在岗 / 已收工几点 / 进程没了但没说收工）
和 `logs\supervision-*.jsonl`（一行一拍的流水，留 7 天）。

「静止」要**两本日志都**安静超过 30 分钟才算 —— MAA 单条任务链十分钟不写日志是常态（实测 10 分 41 秒），只看一本会天天误报；
这道判据故意比主流程自己的 22 分钟停滞线更宽，它兜的是"主流程自己也没醒过来"那种局。
开关在 `config\settings.json` 的 `runtime`：`supervisor`（没写这行就是开）、`supervisorIntervalSeconds`（默认 60）、
`supervisorQuietMinutes`（默认 30）、`supervisorMaxInterventions`（默认 1，写 0 就是纯报告模式，一次都不重启）。

## 3. 两道门：活动图自证（机器每轮）+ 商店领空（人工打点）

**门 1：活动图自证**（「我到底打通了没，脚本每轮自己试一次」）

2026-10-12 起这一道不再要人工确认。每一轮都把当前活动的**最后一关**当探针递给 MAA：

- 进得去（MAA 认库后的关卡名单里有它）＝判为已打通 → 理智照烧活动图；
- 被 MAA 修剪掉＝判为还没打通 → 当日剩余轮改刷长草套餐（理智照烧、不空放），日志里明记这条结论；
  你自己在游戏里打通后，下一轮自动切回活动图，不需要敲任何开关。

结论存在 `state\ark-event-probe.json`（按活动 id + 当天日期记，隔天重判），`status.ps1` 和面板都能看到今天那条。
想立刻压过当天的结论强行刷活动图：

```powershell
.\daily-clear.ps1 -Force            # 本轮忽略活动图自证结论，强行按活动图刷
```

旧的 `-Ack` 与 `config\settings.json` 里的 `ark.eventRequiresAck` 已不再影响判定，只为兼容旧配置留着；
`state\ark-event-ack.json` 里的旧记录从此不参与判定。

**门 2：商店领空**（「活动商店换完了就别再刷活动了」）

```powershell
.\daily-clear.ps1 -ShopDone       # 标记当前活动商店已领空
```

之后每一轮该活动被从候选里剔除，剩余理智改刷长草计划；还有别的已确认活动时会自动改刷那个。
标记按活动 id / 版本号记（`state\ark-shop-done.json`），新版本或新活动自动不适用，**不用记得回来取消**；恢复刷活动用 `-ShopReset`。
不想用这道门：`ark.shopDoneStopsEvent` 改 `false`。

这道门必须手动：MAA 的活动接口只给「活动在不在开、哪些关掉代币」，看不到你的商店兑换进度；
游戏里也没有可靠的「商店已空」信号（MAA 日志里根本没有活动商店相关记录），猜出来的只会误判。

**3.5 智能补材料**

在 `config\settings.json` 的 `ark.farmTargets` 里列出想要的材料，脚本负责「刷到数为止」：

```json
"farmTargets": ["D32钢=30@CE-5", "30115=20"]
```

- 写法：`材料名=目标总数`，`@关卡` 可选（可填多关，逗号分隔）。材料名按 MAA 的 `resource\item_index.json`
  认，也可以直接写数字代号；关卡不填就从掉落学习账本挑「每场平均掉得最多」的关（最多 2 关），账本还没教过
  就明确说不知道该刷哪关，不会瞎猜。
- 现有量是自家账本 `state\ark-inventory.json` 从 MAA 每关结算日志的 `(+N)` 增量累计出来的；
  首跑若 MAA 有库存缓存（`data\DepotData.json`）会拿它标定一次初值，并在提示里标「是估算」。
- 两种刷法都只烧当天理智，**都不吃药**：
  - 顺带（默认，`ark.farmAppend=true`）：长草日的理智计划尾部自动拼上 farm 关，活动期不挤占；
  - 专用：`.\daily-clear.ps1 -Farm` 本轮 Fight 链只刷缺口材料，并打开 MAA 原生的
    「指定材料刷到 N（按本次出击掉落计数）」+「刷取次数上限」双保险，单轮场次封顶
    `ark.farmMaxTimesPerRound`（默认 12），剩下的明天接着刷。
- 判表结果在 `status.ps1` 的「材料补刷」行和 DryRun 预览里都能看到；缺口逐日从记账里减，凑够即停。

## 4. 首次使用（新机器上一次性）

> 不想记命令：面板「配 置」页的**自动扫描并保存**就是下面第 0 步的 `setup.ps1`，**保存路径改动**等于手工带那几个参数；
> 「定 时」页的**按现在的时间点注册**就是第 5 节的 `install-task.ps1`。下面写命令本身，是为了知道按钮按下去到底跑了什么。

0. **生成配置**：仓库里只有 `config\settings.example.json`（`settings.json` 被 `.gitignore` 排除，见第 8 节）。

   ```powershell
   pwsh -File setup.ps1 -DryRun     # 只看探测到什么，不写文件
   pwsh -File setup.ps1             # 探测 + 写入 config\settings.json
   pwsh -File setup.ps1 -MaaDir "D:\Tools\MAA" -ArkExe "D:\Games\Arknights\Arknights.exe"   # 探测不到就手工指定
   ```

   探测优先级：**命令行指定 > 现有 `settings.json` 里仍有效的路径 > 正在运行的进程 > 卸载表 > 固定磁盘浅层扫描**。
   每项都打印来源，`Downloads\`、`xx (2)\` 这类副本目录会被排到最后并标注。退出码 `2` = 还有必填项没填（手填也可以）。
   **脚本只保证「路径存在」，不保证那是你想用的那份 MAA 配置**，探测完一定看一眼输出。

1. **允许一次 UAC**：跑 `install-task.ps1` 时点「是」，之后定时和双击 `run-daily.cmd` 都不再弹。
2. **端游由脚本拉起**：MAA 的配置里其实没存端游路径（`StartGame=true` 也只会报「未找到窗口」），所以 `daily-clear.ps1`
   会先启动 `paths.arknightsExe` 指向的端游、等窗口出现、再把 `StartGame` 关掉后启动 MAA 去连。
   端游退出后需要重新登录/更新的话，日常会卡在这一步（报 `not-started` 并通知你，时限 `runtime.arkStartTimeoutMinutes`）。
3. **不要锁屏**：保持登录、允许熄屏即可（运行期间脚本顶住睡眠和熄屏；每轮起跑时也会把屏保关掉，且不再恢复）。
   设了「无人操作自动锁屏」请先关掉 —— 锁屏 = 桌面不可用 = 截图失败；起跑时会话若已被屏保/锁屏桌面接管，本轮直接早退 `not-started` 并写明原因。
   - **"到点会有全屏程序接管输入桌面"这件事可以断根**：`pwsh -File tools\unarm-screensaver.ps1` 只读体检（不加参数一个字节都不写），
     加 `-Apply` 才真动 —— 删的是注册表里挂着的那个 `.scr` 本身，原值先备份进 `state\screensaver.unarm.json`，`-Restore` 可原样装回。
     06:00 那一轮连败的根因就是壁纸引擎注册的 `.scr`：日常脚本只把武装位拨到 0，挂着的 `.scr` 还在，任何一次屏保设置改动都可能把它重新点亮。
4. MAA 那边不需要额外设置，脚本每轮直接改它的配置文件（改前都在 `backups\` 留副本）。

## 6. 出问题怎么查

- `pwsh -File status.ps1` —— 环境、进程、今天判定、MAA 队列、确认状态、最近记录，一次看完。
- **这一份是哪一版**：全工程只有一处写着版本号 —— 仓库根那个 `VERSION` 文件，别的地方都是读它，不是抄它：
  `status.ps1` 环境段的「版本」行、面板标题栏与启动日志、诊断页那个 zip 里的 `版本.txt`、打包好的 exe 的 `--version`
  （只印一行「仓库名 + 版本号」，不动任何程序、不弹界面）。形状不对或文件不在就统一退成 `0.0.0` —— 那是"读不出来"，不是"版本 0"。
  反馈问题时把这一行带上，比截图整屏快。
- `pwsh -File tools\test-ark.ps1` —— 纯逻辑自检（只读：不改配置、不启动任何程序、不发网络请求），
  断言条数由它自己的末行自报（改动越多条数会变，不在这里抄死）。改过 settings 或判定代码后跑一遍最放心。
- `pwsh -File tools\test-modules.ps1` —— 框架层自检（这一路的游戏模块清单齐不齐、入口开关名对不对、判定/预览钩子调不调得动，
  外加一条"源码/文案里不许出现只在这台机器成立"的扫描：安装路径、助手实例 id、视觉 Key、webhook、`%USERPROFILE%`，
  值全部运行时从本机 `config\settings.json` 里取，所以这条不会自己命中自己；红了只报"哪个文件 <- 哪一项"，值不进日志），
  只读。它和上面那份是两套东西，缺哪个都不算过；断言条数同样以它自己的末行自报为准。
  里面有几条是"钉打包那一侧"的（exe 外壳 `--version`、`build-exe` 盖文件属性、导出归属表），那三个文件本来就不在这棵树里，
  它们会明说"跳过：……不进导出仓库"而不是跟着计数装绿 —— 看到 PASS 后面带"跳过"是设计，不是漏测。
- `pwsh -File tools\test-lib.ps1` —— 共用底座的离线自检（日志/JSON/备份/进程那几层）。
- `pwsh -File tools\unarm-screensaver.ps1` —— 屏保体检与断根（**不加参数=只读**，把现值、要动哪几项、动完的复检打出来，一个字节都不写；
  `-Apply` 才真写，`-Restore` 按备份装回去）。退出码只读和 `-Apply` 同一套：0=已断根 / 1=还没断根 / 2=读不到注册表或没有备份，
  所以脚本判"这一轮会不会被屏保接管"直接判它就行。`status.ps1` 的「屏保」行读的是同一套结论。
- 怀疑今天判得不对 → 先看 `state\ark-event-probe.json`（每轮对活动最后一关的自证结论：活动 id、日期、结论各一条），
  再用 `pwsh -File daily-clear.ps1 -DryRun` 打出这一轮的判定与将要改的配置（什么都不改、不启动）。
- **一轮跑完是 `stalled`、MAA 一直在点同一个按钮** → 先在 `logs\` 那一轮里搜 `点击环境探测`，那行会写当时输入桌面叫什么、
  端游在不在前台、窗口状态和光标位置；再搜 `抢前台` 那句（脚本判到"点了没推进"时会自己抢一次并把现场带上）。
  输入桌面不是 `Default` → 会话没在正常桌面，鼠标键盘进不来，按 [第 2.2 节](#22-无人值守那一轮为什么可能认到按钮却点不动) 处理。
  **别用 `asst.log` 里的 `inject_input_event` 判断点击通不通**：那些注入全部来自基建向左滑，点击从来都走发消息，
  成功轮也一样 —— 它的有无只反映"这一轮走没走到滑动那一步"。要看的是同一个子任务的 `"exec_times"` 在不在一路涨。
- MAA 自己的日志：`<maaDir>\debug\gui.log`（目录见 `config\settings.json` 的 `paths`）。
  **gui.log 静默的时候 `debug\asst.log` 往往还在写** —— 那是 MAA 内核的流水账，里面的
  `"cur_task"` / `"exec_times"` / `Win32Controller click` 能告诉你它到底卡在哪个子任务、在同一点上重复了多少次
  （脚本判到卡住时会把这条线索直接写进结论，`paths.maaAsstLog` 可改路径）。
- 被脚本改过的配置都在 `backups\` 留了最近 20 份，出问题直接覆盖回去即可。

判定规则小结：

| | 成功 | 卡住 |
| --- | --- | --- |
| MAA | `gui.log` 出现 `任务已全部完成！` | MAA 自己的「日志无更新/停滞」告警，或 22 分钟无新日志（`stalled`，宣布之前会先试一次[视觉兜底](#21-被弹窗挡住时的视觉兜底可选默认开着)）；`gui.log` 出现「任务已完成，但出现错误！」而链路没跑齐 → 不再等那 22 分钟，当场兜底一次后立刻 `stalled`，交给外层那一次重试（它会关端游重开、重起 MAA 再跑一遍），见 [第 2.1 节](#21-被弹窗挡住时的视觉兜底可选默认开着)；`asst.log` 里同一个子任务重试 ≥60 次且一条链路都没完成 → 也是 `stalled`，会先抢一次前台再早退，见 [第 2.2 节](#22-无人值守那一轮为什么可能认到按钮却点不动)；端游没被拉起且无链路完成（`not-started`）；日志在涨却一条标志都没认出 → `unknown-format` |

`unknown-format` 是唯一「结果不可信」的状态：它不猜原因，只告诉你别按这一轮判定理智是否清完。

失败会自动重试一次（`runtime.retryOnce`），但 `not-started` / `unknown-format` 不重试（重试只是白等）；再失败就收尾 + 弹通知，不会整晚挂着。

  tools\gdcore\ tools\gdinterop\  进程内现编的 C# 内核支撑与 Win32 现场手脚（PrintWindow 拍窗口、抢前台、真实鼠标点击、顶住睡眠）

  tools\vision-ask.ps1 只问不点：把现屏交给模型、原样打印回答，一次点击都不做
  tools\unarm-screensaver.ps1 屏保体检/断根（默认只读；-Apply 删注册表挂的 .scr，-Restore 装回，见第 4 节第 3 条）

  tools\check-ps51.ps1 编码与行尾守卫

依赖：**下载页的 exe 零依赖** —— 自带官方 PowerShell 运行时（跟 exe 一对的那枚 `game-daily-ark-engine.zip` 附件；
两枚放同一文件夹，首次双击自动释放到本机用户目录；机器上装没装 PowerShell、装的哪个版本，都不影响）。
**从这份仓库直接跑**（双击 `.cmd`、或 `pwsh -File …`）要 PowerShell 7（`pwsh`）——本仓库只支持 7。`run-daily.cmd` 会自己找 pwsh（PATH 或装机版），一个都找不到会提示装法：
`winget install Microsoft.PowerShell`（或到官网下载装上）。下文命令一律用 `pwsh`。
不需要 adb。

视觉 Key、webhook、`%USERPROFILE%`）扫一遍源码和文案，防止某次改动顺手把你机器的路径写进了注释或样本；
红了只报「哪个文件 <- 哪一项」，值本身不进日志（日志会进诊断包递给人看）。

**这个仓库往外发的东西一共三处**，都不带密钥：① 判定活动时 `ark.activityApiUrl` 那一次 GET（就是 MAA 自己也在用的公开接口）；
② 你填了 `notify.webhook` 才发的每轮结果；③ [第 2.1 节](#21-被弹窗挡住时的视觉兜底可选默认开着)兜底时的一张端游窗口截图
（要你自己配了模型 key 才会有，没配就是不发）。除这三处之外脚本不联网。
